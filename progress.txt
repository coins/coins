## Codebase Patterns
- Use `bincode::serde::decode_from_slice` with `bin_config()` for deserialization
- Use `bincode::serde::encode_to_vec` with `bin_config()` for serialization
- All Rust crates are in `crates/` directory
- Types shared across crates go in `coins-types` crate
- Crypto operations (BLS signatures) are in `coins-crypto` crate
- Core validation logic is in `coins-core` crate
- Frontend uses Bulma CSS framework
- Explorer frontend is vanilla JS in `crates/coins-explorer/src/web/static/`
- Wallet frontend is vanilla JS in `crates/coins-wallet/static/`
- Transaction size is fixed: sender_id(4) + recipient_pk(32) + token_id(2) + amount(4) + fee(1) = 43 bytes
- G1 public keys are 32 bytes, G2 signatures are 64 bytes
- Account IDs are u32, starting from 0
- Native token is token_id = 0
- Fees are always paid in native token
- Publisher has a mempool overlay (mempool.rs) that mirrors validator balance logic - keep in sync with validator changes
- Test files are in `crates/*/tests/` and examples in `crates/*/examples/` - struct changes require updating all of these
- When changing Account or Transaction structs, always run `cargo test --all` to catch test failures across ALL crates
- Use `account.native_balance()` to read native balance, `account.balances.insert(TOKEN_ID, value)` to set
- Prefer constants (TX_SIZE, COMPACT_TX_SIZE) over magic numbers in test assertions
- Integration test scripts are in `scripts/` folder: test-regtest.sh, test-mutinynet.sh, test-ibd.sh, test-explorer.sh, test-publish-formats.sh
- Use `scripts/setup-regtest.sh` to start local regtest environment, `scripts/stop-regtest.sh` to stop it
- Use `scripts/setup-mutinynet.sh` to connect to mutinynet testnet
- Axum servers use tower-http for static file serving
- Axum uses `:param` syntax for path parameters (not `{param}`)
- WASM crates need getrandom with "js" feature for browser random number generation
- WASM build requires lld linker - add `llvmPackages.lld` to flake.nix buildInputs
- Build WASM with: `wasm-pack build --target web crates/coins-wallet/wasm`
- WASM pkg/ directory is gitignored (build artifacts) - files must be rebuilt after clone
- Wallet uses Web Crypto API: PBKDF2 (100k iterations) + AES-GCM for key encryption
- Wallet stores encrypted key in localStorage, session key in sessionStorage
- Mutinynet indexer runs on port 8083, publisher on port 8082
- Regtest indexer runs on port 8084, publisher on port 8080

- **Files changed:**
  - crates/coins-publisher/src/api.rs: Added bin_config import and changed deserial ization call

- **Learnings for future iterations:**
  - **CRITICAL**: Always use bin_config() from coins_types for all Transaction serialization/deserialization
  - The wallet WASM (crates/coins-wallet/wasm/src/lib.rs) calls tx.serialize() which uses bin_config()
  - The publisher API must match this configuration to deserialize wallet transactions
  - Check Codebase Patterns section first - it already documented the bin_config() requirement
  - bincode::config::standard() != bin_config() - they produce incompatible wire formats
  - This bug would cause all wallet-submitted transactions to fail with "invalid transaction data" error
